# FretPath — เอกสารออกแบบระบบ (Design Spec)

ระบบเรียนกีตาร์พื้นฐานออนไลน์แบบก้าวต่อก้าว · โปรเจกต์จบปี 4
วันที่: 2026-10-19 · สถานะ: รอทีมตรวจทาน

---

## 1. ภาพรวม

### 1.1 เป้าหมาย
- สร้างเว็บไซต์สอนกีตาร์พื้นฐานสำหรับผู้เริ่มต้น ที่เรียนเป็นลำดับ วัดผลด้วยแบบทดสอบ และติดตามการฝึกซ้อมได้
- ใช้เป็นโปรเจกต์จบปี 4 โดยมีผลงาน 2 ด้านเท่ากัน: **ตัวระบบ** และ **งานประกันคุณภาพ (QA)**
- รอบนี้ยังไม่หารายได้ แต่โครงสร้างข้อมูลต้องรองรับการขายคอร์สในอนาคตโดยไม่ต้องรื้อระบบ

### 1.2 ทีม
| บทบาท | ความรับผิดชอบ |
|---|---|
| Developer (1 คน) | โค้ดทั้งหมด: ฐานข้อมูล, RLS, ฟังก์ชันฝั่งเซิร์ฟเวอร์, หน้าเว็บ, หลังบ้านแอดมิน, pgTAP สำหรับ `submit_quiz` และ RLS |
| QA (1 คน) | เอกสาร QA ทั้งหมด, Playwright (UI E2E + API/security), ดูแล CI/GitHub Actions, รีวิว PR ด้านคุณภาพ |

### 1.3 ข้อจำกัด
- **ค่าใช้จ่าย 0 บาท:** ใช้เฉพาะแผนฟรี (Vercel Hobby, Supabase Free, GitHub Free)
- **ไม่มีคนเฝ้าระบบ:** เว็บต้องเปิดได้ตลอดเวลา งานดูแลต้องเป็นอัตโนมัติ
- **ต้นแบบหน้าตา:** ไฟล์ HTML "FretPath" ที่ทีมมีอยู่ (Tailwind) ใช้เป็นต้นแบบ UI
- **ห้ามใช้เชิงพาณิชย์บน Vercel Hobby:** วันที่เริ่มขายคอร์สหรือรับเงินใด ๆ (รวมถึงรับบริจาค) ต้องย้ายไปแผนที่อนุญาตเชิงพาณิชย์ก่อน

### 1.4 ข้อที่รอยืนยัน
- **กำหนดส่ง / วันเดโม:** ทีมจะแจ้ง ใช้สำหรับวางลำดับงานในแผนการพัฒนา (ไม่กระทบการออกแบบในเอกสารนี้)

## 3. สถาปัตยกรรม

```
 เบราว์เซอร์ผู้ใช้
      │  HTTPS
      ▼
 Vercel (Hobby) ── Next.js App Router + TypeScript + Tailwind
      │            • Server Components / Server Actions
      │            • Middleware ตรวจเซสชันและสิทธิ์หน้า
      ▼
 Supabase (Free)
   • Auth      อีเมล+รหัสผ่าน, ยืนยันอีเมล, รีเซ็ตรหัส, Google (S)
   • Postgres  ตาราง + Row Level Security + ฟังก์ชัน submit_quiz
   • Storage   รูปภาพบทเรียน (bucket สาธารณะสำหรับเนื้อหาที่เผยแพร่)

 YouTube (Unlisted) ── วิดีโอบทเรียน (ฝังด้วย iframe)

 GitHub
   • Repo เดียว, ป้องกัน branch main
   • Actions: CI บน PR, ชุดเทสต์เต็มทุกคืน, keep-alive, backup
```

**หลักการ**
- ตรรกะที่เกี่ยวกับความปลอดภัย (คะแนน, การปลดล็อก, สิทธิ์) อยู่ในฐานข้อมูล ไม่พึ่งการซ่อนปุ่มในหน้าเว็บ
- เครื่องมือเสียง (ดีดสาย, คอร์ด, เมโทรนอม, ตัวจับเวลา) ทำงานในเบราว์เซอร์ล้วนด้วย Web Audio API ไม่ต้องใช้เซิร์ฟเวอร์
- ย้ายดีไซน์จากต้นแบบ FretPath เป็นคอมโพเนนต์ React; รูปที่ฝังเป็น base64 ในต้นแบบแยกออกเป็นไฟล์รูป

## 4. ฐานข้อมูล

### 4.1 ความสัมพันธ์
```
courses ─┬─< lessons ─┬── lesson_contents (เนื้อหา, เห็นเมื่อปลดล็อก)
         │            ├─< quiz_questions ─┬─< quiz_choices
         │            │                   └── quiz_answer_keys (ลับ)
         │            ├─< lesson_progress >── profiles
         │            └─< quiz_attempts ─< quiz_attempt_answers
         └─< enrollments >── profiles ──< practice_logs
```

### 4.2 ตาราง
ทุกตารางมี `id uuid` (ยกเว้นที่ระบุ), `created_at`, `updated_at`

| ตาราง | คอลัมน์ | ข้อจำกัดสำคัญ |
|---|---|---|
| `profiles` | `id` (FK auth.users), `display_name`, `avatar_url`, `role`, `weekly_goal_minutes` | `role ∈ {member, admin}` ค่าเริ่มต้น member; `weekly_goal_minutes` 0–5000 |
| `courses` | `slug`, `title`, `description`, `cover_url`, `is_free`, `price_thb`, `status`, `sort_order` | `slug` unique; `status ∈ {draft, published}`; `price_thb` null ได้ |
| `enrollments` | `user_id`, `course_id`, `source`, `enrolled_at` | PK (`user_id`, `course_id`); `source ∈ {free, purchase}` |
| `lessons` | `course_id`, `slug`, `title`, `summary`, `sort_order`, `pass_score`, `status` | (`course_id`, `slug`) unique; `pass_score` 1–100 ค่าเริ่มต้น 60 — เป็น "ข้อมูลหัวบท" ที่หน้าเส้นทางเรียนใช้แสดงทุกบท รวมถึงบทที่ล็อก |
| `lesson_contents` | `lesson_id` (PK), `content_md`, `video_url` | แยกจาก `lessons` เพื่อให้ RLS ซ่อนเนื้อหาบทที่ยังล็อกได้; `video_url` ต้องเป็นลิงก์ YouTube |
| `quiz_questions` | `lesson_id`, `prompt`, `image_url`, `explanation`, `sort_order` | — |
| `quiz_choices` | `question_id`, `text`, `sort_order` | ตัวเลือก 2–6 ข้อต่อคำถาม (ตรวจตอนเผยแพร่) |
| `quiz_answer_keys` | `question_id` (PK), `correct_choice_id` | `correct_choice_id` ต้องเป็นตัวเลือกของคำถามเดียวกัน |
| `lesson_progress` | `user_id`, `lesson_id`, `status`, `best_score`, `completed_at` | PK (`user_id`, `lesson_id`); `status ∈ {unlocked, completed}`; ไม่มีแถว = ล็อก |
| `quiz_attempts` | `user_id`, `lesson_id`, `score_pct`, `passed`, `submitted_at` | `score_pct` 0–100 |
| `quiz_attempt_answers` | `attempt_id`, `question_id`, `choice_id`, `is_correct` | PK (`attempt_id`, `question_id`) |
| `practice_logs` | `user_id`, `practiced_on`, `minutes`, `activity`, `note`, `lesson_id` | `minutes` 1–600; `practiced_on ≤ วันนี้ (Asia/Bangkok)`; `note` ≤ 500 ตัวอักษร |

ตัวเลขใน Dashboard คำนวณจากตารางเหล่านี้ (ไม่มีตารางสรุปแยก)

### 4.3 สิทธิ์ (Row Level Security)
| ตาราง | ผู้ไม่ล็อกอิน | ผู้เรียน | แอดมิน |
|---|---|---|---|
| `courses` | อ่านที่ published | อ่านที่ published | ทั้งหมด |
| `lessons` | — | อ่านที่ published ในคอร์สที่ลงทะเบียน (ทุกบท รวมบทที่ล็อก) | ทั้งหมด |
| `lesson_contents`, `quiz_questions`, `quiz_choices` | — | อ่านเฉพาะบท published ในคอร์สที่ลงทะเบียน **และปลดล็อกแล้ว** | ทั้งหมด |
| `quiz_answer_keys` | — | **ไม่มีสิทธิ์** | ทั้งหมด |
| `profiles` | — | อ่าน/แก้ของตัวเอง ยกเว้น `role` | อ่านทั้งหมด, แก้ `role` |
| `enrollments`, `lesson_progress`, `quiz_attempts`, `quiz_attempt_answers` | — | อ่านของตัวเองเท่านั้น (เขียนผ่านทริกเกอร์/ฟังก์ชัน) | อ่านทั้งหมด |
| `practice_logs` | — | อ่าน/เพิ่ม/แก้/ลบของตัวเอง | อ่านทั้งหมด |

### 4.4 ฟังก์ชันและทริกเกอร์
**`handle_new_user` (ทริกเกอร์เมื่อสร้างผู้ใช้ใน Auth)** — สร้าง `profiles` (role = member), ลงทะเบียนคอร์สฟรีที่ published, ปลดล็อกบทแรกของแต่ละคอร์ส

**`submit_quiz(lesson_id uuid, answers jsonb)`** — `security definer`, ทำงานใน transaction เดียว
1. ตรวจว่าผู้เรียนล็อกอิน, ลงทะเบียนคอร์ส, และบทนี้ปลดล็อกแล้ว — ไม่ผ่านให้ error `LESSON_LOCKED`
2. ตรวจว่าตอบครบทุกคำถามของบทและทุกตัวเลือกเป็นของคำถามนั้น — ไม่ผ่านให้ error `INVALID_ANSWERS`
3. ให้คะแนนจาก `quiz_answer_keys`: `score_pct = round(ถูก / ทั้งหมด × 100)`
4. บันทึก `quiz_attempts` และ `quiz_attempt_answers`
5. อัปเดต `lesson_progress.best_score = max(เดิม, ใหม่)`
6. ถ้า `score_pct ≥ pass_score`: ตั้งบทนี้เป็น completed และปลดล็อกบท published ถัดไปตาม `sort_order` (ถ้ามี)
7. คืนค่า: คะแนน, ผ่าน/ไม่ผ่าน, เฉลยและคำอธิบายรายข้อ, slug บทถัดไป

**`unlock_after_publish` (ทริกเกอร์เมื่อบทเปลี่ยนเป็น published)** — ปลดล็อกบทนั้นให้ผู้เรียนที่ completed บท published ก่อนหน้าแล้ว (FR-03.5)

**`delete_lesson` guard** — ห้ามลบบทที่มีแถวใน `lesson_progress` หรือ `quiz_attempts` (FR-07.6)

## 5. การใช้งานหลักและการจัดการข้อผิดพลาด

### 5.1 สมัครและล็อกอิน (FR-01)
สมัคร → ยืนยันอีเมล → `handle_new_user` ทำงาน → เข้า Dashboard
- อีเมลรูปแบบผิด / รหัสสั้นกว่า 8 ตัว: ข้อความภาษาไทยใต้ช่อง
- ล็อกอินผิด: แสดง "อีเมลหรือรหัสผ่านไม่ถูกต้อง" (ไม่บอกว่ามีบัญชีหรือไม่)
- ลืมรหัสผ่าน: แสดงข้อความเดียวกันเสมอ "ถ้ามีบัญชีนี้ เราได้ส่งลิงก์ไปแล้ว"
- เซสชันหมดอายุ: พาไป `/login?next=<หน้าเดิม>` แล้วกลับหน้าเดิมหลังล็อกอิน

### 5.2 เรียนบทเรียน (FR-02, FR-03)
เส้นทางเรียน → เปิดบท → อ่าน/ดูวิดีโอ/ดีดสาย → ทำแบบทดสอบ
- เปิดบทที่ล็อก: redirect ไป `/path` พร้อมข้อความ "ต้องผ่านแบบทดสอบบท X ก่อน"
- วิดีโอโหลดไม่ได้: ส่วนอื่นแสดงปกติ พร้อมข้อความในกรอบวิดีโอ
- เบราว์เซอร์ไม่รองรับเสียง: ปุ่มเสียงแสดงสถานะใช้ไม่ได้ ไม่ทำให้หน้าพัง

### 5.3 ทำแบบทดสอบ (FR-04)
ตอบครบ → ส่ง → `submit_quiz` → หน้าผลลัพธ์
- ผ่าน: ปุ่ม "ไปบทถัดไป" (หรือ "จบคอร์สแล้ว" ถ้าเป็นบทสุดท้าย)
- ไม่ผ่าน: ปุ่ม "ทบทวนบทเรียน" และ "สอบใหม่"
- ระหว่างรอผล: ปุ่มส่งถูกปิด
- เครือข่ายล้มเหลว: คำตอบยังอยู่ แสดงปุ่ม "ส่งอีกครั้ง"

### 5.4 บันทึกการฝึก (FR-05)
จับเวลาหรือกรอกนาที → เลือกหัวข้อ → บันทึก → แสดงใน Dashboard
- ตรวจ 1–600 นาที และวันที่ไม่เกินวันนี้ ทั้งในฟอร์มและด้วย CHECK constraint

### 5.5 แอดมิน (FR-07)
สร้าง/แก้เป็นฉบับร่าง → เพิ่มคำถาม → (ดูตัวอย่าง) → เผยแพร่
- เผยแพร่ไม่ผ่านเงื่อนไข FR-07.5: แสดงรายการสิ่งที่ยังขาด
- ลบบทที่มีผู้เรียน: แสดงทางเลือก "เปลี่ยนเป็นฉบับร่าง"

### 5.6 ทั่วไป
ทุกหน้ามีสถานะกำลังโหลด และหน้า error ภาษาไทยพร้อมปุ่มลองใหม่ (`error.tsx`, `not-found.tsx`)

### 6.2 เทคนิคออกแบบเทสต์ที่ใช้
| เทคนิค | ตัวอย่างในระบบ |
|---|---|
| Boundary Value Analysis | นาทีฝึก 0/1/600/601; คะแนน 59/60 ที่ `pass_score` 60; รหัสผ่าน 7/8 ตัว |

### 6.3 Automated Testing (Playwright + TypeScript)
**โครงสร้าง**
```
e2e/
  pages/        Page Objects (LoginPage, PathPage, QuizPage, PracticePage, AdminLessonPage …)
  fixtures/     fixture: memberPage, adminPage, testData (สร้าง/ล้างข้อมูล)
  api/          API/security tests ผ่าน request context ไปที่ Supabase REST/RPC
  specs/        UI E2E แยกตาม FR
  utils/        Supabase admin client (ใช้เฉพาะในเทสต์), ตัวสร้างข้อมูล
playwright.config.ts
```

**แนวทาง**
- **ล็อกอิน:** `storageState` แยกตาม role สร้างครั้งเดียวใน setup project
- **ข้อมูลทดสอบ:** สร้างผู้ใช้และข้อมูลผ่าน Supabase Admin API ในแต่ละเทสต์ และล้างหลังจบ เทสต์จึงเป็นอิสระต่อกันและรันขนานได้
- **ตัวระบุ element:** ใช้ `getByRole` / `getByLabel` เป็นหลัก และ `data-testid` สำหรับ element ที่ไม่มีชื่อชัดเจน
- **ป้าย:** `@smoke` (เส้นทางหลัก), `@regression` (ทั้งหมด), `@security` (RLS/สิทธิ์)
- **Projects:** Chromium, Firefox, Mobile (Pixel 7 viewport)
- **รายงาน:** HTML report; เก็บ trace, video, screenshot เมื่อล้มเหลว

**เส้นทางหลักที่ต้องมี (`@smoke`)**
1. สมัคร → บท 1 ปลดล็อก → สอบไม่ผ่าน → บท 2 ยังล็อก → สอบผ่าน → บท 2 ปลดล็อก
2. บันทึกการฝึก → ตัวเลขใน Dashboard เปลี่ยนตาม
3. แอดมินสร้างบท (draft) → ผู้เรียนไม่เห็น → เผยแพร่ → ผู้เรียนเห็น

**API / Security tests (`@security`) — ตัวอย่าง**
- ผู้เรียนดึง `quiz_answer_keys` ได้ผลว่าง/ถูกปฏิเสธ
- ผู้เรียน insert/update `quiz_attempts` หรือ `lesson_progress` ตรง ๆ ถูกปฏิเสธ
- ผู้เรียน update `profiles.role` ของตัวเองเป็น admin ถูกปฏิเสธ
- ผู้เรียน A อ่าน `practice_logs` ของผู้เรียน B ไม่ได้
- เรียก `submit_quiz` กับบทที่ล็อกได้ error `LESSON_LOCKED`
- ผู้ไม่ล็อกอินอ่าน `lessons` ไม่ได้
- ผู้เรียนอ่าน `lesson_contents` และ `quiz_questions` ของบทที่ยังล็อกไม่ได้

## 7. การทำงานร่วมกันและงานอัตโนมัติ

### 7.1 Workflow
- Repo เดียวบน GitHub; branch `main` ถูกป้องกัน ห้าม push ตรง
- ทุกงานทำใน branch แยก แล้วเปิด Pull Request
- PR merge ได้เมื่อ: CI ผ่าน + QA approve
- โครงสร้างฐานข้อมูลเปลี่ยนผ่านไฟล์ migration ใน `supabase/migrations/` เท่านั้น
- **Shift-left:** QA เขียน Test Cases จากสเปกนี้ได้ทันที; Developer พัฒนาตามลำดับ FR-01 → FR-07 และ QA ทดสอบแต่ละ FR เมื่อเสร็จ

### 7.2 GitHub Actions (QA ดูแล)
| Workflow | เมื่อไหร่ | ทำอะไร |
|---|---|---|
| `ci.yml` | ทุก PR | lint, type-check, build, pgTAP, Playwright `@smoke` (Chromium) |
| `nightly.yml` | ทุกคืน 02:00 น. (Asia/Bangkok) | Playwright ชุดเต็มทุก project, อัปโหลด HTML report |
| `keep-alive.yml` | ทุก 2 วัน | query เล็ก ๆ ไปที่ Supabase production เพื่อกันการหยุดโปรเจกต์ |
| `backup.yml` | ทุกสัปดาห์ | `pg_dump` ฐานข้อมูล production เก็บเป็น workflow artifact (เก็บ 90 วัน) |

workflow ที่ล้มเหลวจะส่งอีเมลแจ้งผู้ดูแล repo โดยอัตโนมัติ
ความลับ (Supabase URL/keys, DB connection string) เก็บใน GitHub Secrets เท่านั้น
`backup.yml` ใช้ connection string แบบ Session Pooler ของ Supabase (รองรับ IPv4 ซึ่ง GitHub runner ใช้)
Preview ใช้ฐานข้อมูล production ดังนั้น PR ที่มี migration ใหม่ให้ตรวจบน Local/CI ก่อน และรัน migration บน production หลัง merge

- Vercel เชื่อม repo: merge เข้า `main` = deploy production; ทุก PR ได้ Preview URL
