# FretPath — สคริปต์เดโม 10 นาที (production)

สคริปต์สำหรับสาธิตเส้นทางหลัก 1–3 ของสเปกข้อ 6.3 บนเว็บ **production** จริง ใช้เวลารวมประมาณ 10 นาที

> **กติกาเหล็ก:** ห้ามใช้บัญชีจาก `supabase/seed.sql` (`member@fretpath.test`, `admin@fretpath.test`) และห้ามพิมพ์รหัสผ่านใด ๆ ให้ผู้ชมเห็นบนจอ — บัญชี seed ต้องไม่มีบน production (ตรวจโดย TC-PRD-04) บัญชีเดโมทั้งหมดทีมสร้างเองตามด้านล่าง และลบทิ้งหลังเดโม

## 0. เตรียมก่อนเดโม (ทำล่วงหน้าอย่างน้อย 1 ชั่วโมง ใช้เวลา ~15 นาที)

เงื่อนไข: production ออนไลน์ตาม `docs/deploy/*.md` (รวมขั้นสร้างแอดมินคนแรก) และ TC-PRD-05 ผ่านแล้ว (ลิงก์อีเมลใช้ได้จริง)

1. **บัญชีผู้เรียนเดโม (สร้างสดตอนเดโม)** — ใช้อีเมลจริงที่รับได้ ที่ยังไม่เคยสมัคร เช่น alias `ชื่อคุณ+demo1@<โดเมนอีเมล>` ผู้เรียนที่สอบผ่านแล้วรีเซ็ตสถานะไม่ได้ ดังนั้น **การเดโมแต่ละรอบต้องใช้อีเมลใหม่** (`+demo2`, `+demo3` …) เตรียมอีเมลสำรองไว้ 2 รอบ
2. **บัญชีแอดมินเดโม** — สมัครบัญชีจริงด้วยอีเมลของทีม ยืนยันอีเมล แล้วตั้ง `role = 'admin'` ตาม `docs/deploy/supabase.md` ขั้นที่ 9 (ห้ามใช้บัญชีแอดมินของ seed) ทดสอบเข้า `/admin` ให้ได้ก่อนเดโม และเก็บรหัสผ่านไว้ใน password manager
3. **เบราว์เซอร์ 2 โปรไฟล์** (หรือหน้าต่าง Incognito คู่กับหน้าต่างปกติ): โปรไฟล์ **ผู้เรียน** และโปรไฟล์ **แอดมิน** เปิดค้างไว้คนละหน้าต่าง เปิดกล่องอีเมลของผู้เรียนเดโมไว้อีกแท็บ (ใช้เปิดลิงก์ยืนยัน)
4. **เฉลยแบบทดสอบบทที่ 1** — ผู้นำเสนออ่านเฉลยจาก `supabase/content/guitar-basics.sql` ไว้ล่วงหน้า (ผู้เรียนจริงเห็นเฉลยไม่ได้ก่อนส่ง) จดว่าข้อไหนตอบอะไรจึงได้ 40% (ตอบผิดเกือบทั้งหมด) และข้อไหนทั้งหมดถูกจึงได้ 100%
5. **ตรวจสุขภาพระบบ:** เปิด `https://<โดเมน production>/api/health` ต้องได้ `{"ok":true}` และเปิดหน้าแรกให้เห็นหัวข้อ FretPath
6. สำรอง: ถ้าอีเมลล่าช้าเกิน 1 นาที ให้ข้ามไปทำเส้นทางที่ 2–3 ก่อนแล้วกลับมา (ดูหัวข้อ "ถ้าติดขัด")

บันทึกก่อนเริ่ม (ทีมกรอก): โดเมน production <!-- รอผล: โดเมน production จริงหลังทำตาม docs/deploy/vercel.md --> · อีเมลผู้เรียนเดโมรอบนี้ <!-- รอผล: alias ที่ใช้ (ไม่ต้องเขียนรหัสผ่าน) --> · อีเมลแอดมินเดโม <!-- รอผล: อีเมลแอดมินที่สร้างตาม supabase.md ขั้นที่ 9 -->

## 1. เปิดตัว (0:00 – 1:00)

**พูด:** "FretPath คือเว็บเรียนกีตาร์สำหรับคนไทย เรียนทีละบท ต้องสอบผ่านจึงปลดล็อกบทถัดไป และมีบันทึกการฝึกกับ Dashboard ตรรกะสำคัญ ทั้งคะแนน การปลดล็อก และสิทธิ์ อยู่ที่ฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ"

**ทำ (หน้าต่างผู้เรียน):**
1. เปิด `https://<โดเมน production>/` ให้เห็นหัวข้อ FretPath และคำอธิบายคอร์ส เห็นสัญลักษณ์ https
2. กดไปที่หน้าสมัครสมาชิก (`/signup`)

## 2. เส้นทางหลักที่ 1 (1:00 – 5:30): สมัคร → สอบ → ปลดล็อก

| ขั้น | ทำ | ผลที่ต้องเห็น |
|---|---|---|
| 1 | สมัครด้วยอีเมลเดโม (alias) และรหัสผ่านที่ยาวอย่างน้อย 8 ตัว (อย่าให้ผู้ชมเห็นรหัสผ่าน) | ข้อความว่าส่งลิงก์ยืนยันแล้ว |
| 2 | สลับไปกล่องอีเมล เปิดอีเมลยืนยัน กดลิงก์ | หน้ากลาง "ยืนยันอีเมล" ที่มีปุ่ม **ยืนยันและเข้าสู่ระบบ** (ป้องกันตัวสแกนอีเมลใช้ลิงก์ทิ้ง — TC-AUTH-17) |
| 3 | กด **ยืนยันและเข้าสู่ระบบ** | เข้า `/dashboard` เห็นหัวข้อ Dashboard (ยังไม่มีบันทึกการฝึก) |
| 4 | เปิดเมนู **เส้นทางเรียน** (`/path`) | บทที่ 1 "ปลดล็อก" บทที่ 2 ขึ้นไป "ล็อก" |
| 5 | เปิดบทที่ 1 อ่านเนื้อหาสั้น ๆ (ถ้ามีปุ่มสายเปล่า กดให้ฟังเสียง) แล้วไปหน้าแบบทดสอบ | เห็นคำถามทั้งชุด **ไม่มีเฉลย** ก่อนส่ง |
| 6 | **สอบไม่ผ่านโดยตั้งใจ:** ตอบให้ได้ประมาณ 40% (จากเฉลยที่จดไว้) กด **ส่งคำตอบ** | คะแนน **40%** ไม่ผ่าน (เกณฑ์ 60%) มีให้ทบทวนและสอบใหม่ |
| 7 | กลับ `/path` | บทที่ 2 **ยังล็อก** |
| 8 | สอบอีกครั้ง **ตอบถูกทั้งหมด** แล้วส่ง | คะแนน **100%** ผ่าน เห็นคำอธิบายเฉลย |
| 9 | กลับ `/path` | บทที่ 1 "เรียนจบแล้ว" บทที่ 2 **ปลดล็อก** |

**พูดประกอบขั้น 6–9:** "คะแนนและการปลดล็อกคำนวณในฐานข้อมูลผ่านฟังก์ชัน `submit_quiz` ผู้เรียนส่งคำตอบได้ แต่เขียนคะแนนหรือสถานะบทเองตรง ๆ ไม่ได้ และอ่านเฉลยก่อนส่งไม่ได้ (ตรวจใน TC-SEC-01, TC-SEC-02)"

## 4. เส้นทางหลักที่ 3 (7:30 – 9:30): แอดมินสร้างบท → ฉบับร่าง → เผยแพร่

| ขั้น | ทำ (หน้าต่าง) | ผลที่ต้องเห็น |

| 1 | (แอดมิน) ล็อกอินด้วยบัญชีแอดมินเดโม เข้า `/admin` เลือกจัดการบทเรียน แล้วกด **เพิ่มบทเรียน** | ฟอร์มสร้างบทใหม่ |
| 2 | กรอก **ชื่อบท** เช่น "เดโม: คอร์ดแรก", **slug** เช่น `demo-first-chord` (ภาษาอังกฤษพิมพ์เล็กและขีด), **สรุป**, **เนื้อหา (Markdown)** เช่น `# คอร์ด C`, **เกณฑ์ผ่าน (%)** = 60 แล้วกด **สร้างบทเรียน** | ไปหน้าแก้ไขบท แสดง "สถานะ: ฉบับร่าง" |

**พูดประกอบ:** "บทที่ยังเป็นฉบับร่างถูกซ่อนจากผู้เรียนด้วย Row Level Security ที่ฐานข้อมูล และระบบไม่ยอมให้เผยแพร่บทที่ข้อมูลไม่สมบูรณ์ (ไม่มีคำถาม ไม่มีข้อถูก ตัวเลือกผิดจำนวน — TC-ADM-05)"

## 6. เก็บกวาดหลังเดโม (ทำทุกครั้ง)

1. **ลบบทเดโม:** (แอดมิน) เปิดบท "เดโม: คอร์ดแรก" กด **ลบบทเรียน** ถ้าลบไม่ได้เพราะมีผู้เรียนมีสถานะของบทนี้แล้ว (`LESSON_HAS_LEARNERS`) ให้กด **เปลี่ยนเป็นฉบับร่าง** แทน เพื่อไม่ให้ผู้เรียนจริงเห็น
2. **ลบผู้เรียนเดโม:** Supabase Dashboard > Authentication > Users > ค้นหาอีเมลเดโม > Delete user (ข้อมูลฝึก/ผลสอบของผู้ใช้นั้นถูกลบตามไป — ตรวจว่าตารางเกี่ยวข้องไม่เหลือแถวของ user นี้) *ชื่อเมนูใน dashboard ยังไม่ได้ยืนยันกับหน้าจอจริง ดู test-summary หัวข้อ 9 ข้อ 6*
3. ออกจากระบบทุกหน้าต่าง ปิดโปรไฟล์เบราว์เซอร์เดโม
4. ถ้าเปลี่ยนรหัสผ่านบัญชีแอดมินเดโมเพื่อเดโม ให้เปลี่ยนกลับ หรือปิดใช้บัญชีที่ไม่ใช้แล้ว
5. บันทึกผลเดโมที่ท้ายไฟล์นี้: วันที่ ผู้นำเสนอ ปัญหาที่พบ <!-- รอผล: ทีมกรอกหลังซ้อมเดโมบน production จริง: วันที่ / ผู้นำเสนอ / ใช้เวลาจริง / ปัญหาที่พบ (ถ้ามีให้เปิด defect ด้วยเทมเพลต) -->
